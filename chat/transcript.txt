  On the endpoints: the Jacobian lens has to read and edit the model's internal
  activations mid-generation. Azure Foundry's "serverless API" models and Vertex
  Model Garden's hosted APIs only return text, so neither can be used. Instead,
  open-weight models run in our own container on a dedicated GPU. The same
  container serves all three targets:
  - Azure: Azure AI Foundry "managed compute" (an Azure ML online endpoint).
    Script: deploy/azure/deploy.sh.
  - Google Cloud: a Vertex AI online endpoint (the "LLM hosting item" you were
    thinking of). Script: deploy/gcp/deploy_vertex.sh.
  - Google Cloud, simpler option: Cloud Run with an L4 GPU, which scales to
    zero, for models up to about 8B. Script: deploy/gcp/deploy_cloudrun.sh.

  Agents in one conversation can sit on different clouds, which is what the
  cross-family experiments need.

  The six parts:
  1. Lens setup (docs/01): Anthropic released the lens code, and Neuronpedia
     hosts ready-made lenses for Qwen, Llama, Gemma, OLMo and gpt-oss. A
     sanity-check script confirms a model's lens behaves as expected.
  2. Fitting a lens (scripts/fit_lens.py): for models without a published lens;
     it can be split across machines, with job files for both clouds. A GPT-2
     lens fitted on only 20 prompts closely matched the published one (cosine
     similarity 0.96–0.997).
  3. Benchmarks: classic false-belief tasks plus a version recast as LLM agents,
     Hi-ToM, and replays of NARCBench's collusion transcripts. MACE hasn't
     released its code yet, so Exp. 3 reproduces its repeated-delegation setup.
  4. Harness: agents converse through any endpoint, and every turn's text and
     J-space readout is saved under runs/.
  5. Experiments 0–4: one config file per experiment, run with python -m 
     jpeers.cli run configs/<name>.yaml.
  6. Removing or editing J-space during generation: remove the top-k J-space
     directions, with a random-direction control of the same size; remove
     specific words; steer toward words; or swap two concepts. These can be
     applied per request, per agent, per turn, or to just the span where an
     agent reads its peer.

  Pilot results (docs/results_pilot.md). These are small samples on a 1.7B
  model, so they show the pipeline works but don't test the hypotheses:
  - Exp. 0, a warning sign: on false-belief stories the believed location is the
    lens's top token every time. But on the control stories, where the
    character saw the object move, the original location still wins. At 1.7B,
    J-space tracks "where it was first put", not belief. Repeat this at 8B
    before reading anything into the agent experiments.
  - Exp. 1: the partner's name and team words are far more present under team
    framing (p = 0.0002). That's partly trivial, since only the team prompt
    names the partner. The more meaningful measures, such as thinking about the
    partner's half of the work, show no difference yet.
  - Exp. 2: suspicion words are about twice as present when the peer lies, but
    this isn't significant at 10 facts (p = 0.08). The NARCBench replay shows
    nothing at this scale.
  - Exp. 3:
    - The orchestrator's J-space ranks the right specialist above the wrong one
      in 90% of decisions, against 83% behavioural accuracy.
    - A Qwen orchestrator chose the "Qwen-powered" agent 60% of the time against
      a Llama-powered one.
    - It didn't lock onto one peer the way MACE reports for stronger models; it
      mostly alternated.
  - Exp. 4: removing J-space strips the lens readout while the random control
    doesn't, so the edit is targeted. Behavioural changes are still within
    noise. Steering only works at much lower strength than I first set: 0.15
    produced "suspicious suspicious…", and 0.01 is usable.
